# Meadow Navigation and Live Assets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reconcile the complete 6400x6400 Meadow with a reviewed 16px navigation mask, intentional building/NPC placement, coherent live building and human-character art, and any strictly necessary terrain alignment while preserving the approved painterly background and atomic four-crop runtime.

**Architecture:** Extend the existing Meadow control/export/proof pipeline with one authored 400x400 glyph mask and a deterministic generated navigation registry. Keep map authoring at 32px while runtime static-terrain navigation uses the generated 16px player-centre grid. Building lots, footprints, doors, visual anchors, arrivals, and NPC activity anchors remain coordinate-first content. Regenerated transparent atlases stay live and depth sorted; only approved terrain deltas are inpainted into the existing four-crop background package.

**Tech Stack:** TypeScript 6, Vitest, Phaser 4, Playwright, Bun, Sharp, existing Meadow art-control/export/approval tools, built-in image generation, `2d-game-asset-workflow` alpha tooling.

**Spec:** `docs/superpowers/specs/2026-08-23-meadow-collision-live-assets-and-interiors-redesign-design.md`

**Dependency:** Complete `docs/superpowers/plans/2026-08-23-shared-navigation-extraction.md` first. This plan consumes `NavigationMaskSource`, `NavigationGrid`, the shared map adapter, runtime/save delegation, and the Phase-1 parity evidence.

## Global Constraints

- Keep Meadow exactly 200x200 authoring tiles and 6400x6400 world pixels. `MEADOW_ENTRY_TILE_SIZE_PX`, `MeadowEntryControlInputs.tileSizePx`, `LayeredRegionSource.tileSize`, camera bounds, and map dimensions remain 32px-based.
- Change only renderer/navigation walkability to 16px. The committed Meadow source is exactly 400 rows of exactly 400 `.`/`#` glyphs.
- Preserve every map, transition, NPC, quest, shop, dialogue, pickup, discovery, encounter, and progression identity. Coordinates may change only through the approved control layout.
- Keep the current complete Meadow art as style and richness baseline. Do not globally regenerate it. Edit only reviewed geometry-delta masks.
- Preserve the current four-crop runtime. No overlapping crops, repeated objects, seam discontinuities, or live decorative obstacle overlays may be introduced.
- Buildings remain transparent live assets containing structure plus cast shadow only. Player and NPCs remain live. Collision does not derive from image pixels.
- Remove persistent roof labels from normal world rendering; retain `label`/`labelKey` for the area map and UI/accessibility consumers. Add no replacement proximity caption.
- Preserve player `idle`, `walk`, `attack`, and `dead` clip keys, four-frame counts, rates, repeats,
  and collider. Use the dedicated generated attack row for `hero-attack`; preserve decoded RGBA
  pixels for all enemy animation rows exactly.
- Do not start image generation until the complete-map coordinate, navigation, route, lot, door, arrival, NPC-anchor, and camera-crop controls pass Gate 1 and Gate 2 and are approved by the user.
- When image generation starts, explicitly use the `imagegen` skill and built-in image-generation tool. Use `2d-game-asset-workflow` for normalization, transparent export, atlas assembly, manifest wiring, and runtime QA.
- Art is corrected to approved geometry. Do not move approved geometry to rescue an image candidate.
- Preserve unrelated `.playwright-cli/`, `output/`, reports, and the pre-existing modified fallback screenshot. Stage only task-owned files.
- Run shell commands through `rtk`. After each code task, request spec-compliance and code-quality reviews; after each visual gate, present current rendered evidence to the user.
